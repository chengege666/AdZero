# v0.10.3 订阅识别与计数修复

截图中「重新加载成功」和「未独立计数」分别描述加载任务与订阅预检结果。旧校验器要求整份域名列表的每一条记录都符合 hostname 要求；一条无效记录就会令自动识别失败。已有原生订阅继续由后端处理，因此页面能显示加载成功，却没有该订阅的独立数量。

本次读取了 [AdGuardTeam 的 CNAME Trackers 原始列表](https://raw.githubusercontent.com/AdguardTeam/cname-trackers/master/data/combined_disguised_trackers_justdomains.txt)。2026-10-22 下载快照为 7,688,870 字节，SHA-256 为 `02e421eda001d52dbbd09bb899dc588ac0263cbd8e49705da8f5684917d5145a`。其中 22 条记录以前导连字符开头、4 条包含下划线；共 245,052 个去重后的有效域名。上游列表会更新，这些数值是该快照的检查结果。

## 处理方式

- 对纯域名格式，只排除原生 ASCII 域名处理管线本会丢弃的上述两类记录；记录排除条数，返回有效域名集合。注释、空行、重复项不算无效记录。没有任何有效域名时仍拒绝导入。
- 不删除例外、修饰符、通配符或其他规则语法以提取域名；混合 HTML、网址、网页元素和不支持语法仍拒绝整份导入。Hosts、基础 DNS Adblock、用户域名输入和最终后端产物检查保持严格。
- 保存独立数量、排除数量、格式与检查时间。无法识别的既有来源显示「格式未识别」及具体处理提示，不显示虚假数量或合并总数。
- 原始下载快照的完整性验证保持不变；解析证明增加版本，旧证明重新解析正文。可复用的正文不因解析版本升级重新下载。
- 不改动现有 URL、原生后端设置、代理适配及重载确认方式，不新增运行依赖。

升级后，在没有待应用修改时点击一次「更新订阅」，重新检查此前未独立计数的已启用来源。「重新加载」不会强制更新订阅，这一行为继续保留，避免每次重做下载和统计。

## 可复现检查

`scripts/check_source_validation.py --input <下载快照>` 使用实际生产 `source-lib.uc` 自动识别并计数，同时单独执行校验和固定的 adblock-fast 1.2.4-r4 域名过滤表达式、ASCII 限制及排序阶段，再用生产后端产物解析器比较完整域名集合。测试不启动任何 DNS 或代理服务。

该快照的两组结果完全一致：245,052 个有效域名、26 条被排除记录。不是根据总行数估算，也没有把后端合并数量当成单订阅数量。原生 UCI 测试另行覆盖元数据持久化、刷新后旧计数清理、解析证明升级及无重复下载；UI 断言覆盖数量、排除提示和未识别格式说明。

此验证没有连接用户路由器，不能代替终端实际 DNS 与广告过滤验收。完整结果随发行版保存于 [evidence/v0.10.3](evidence/v0.10.3/)。
