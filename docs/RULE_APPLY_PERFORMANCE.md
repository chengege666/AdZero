# v0.10.1 规则缓存与重新加载

此版本保留现有 adblock-fast 和四种代理适配器。独立 DNS、可编辑上游和新的系统流量接管架构暂不实施。

## 已确认的慢操作

用户设备为 OpenWrt 25.12.5 rockchip/armv8。一次成功的 `settings-apply` 在进入代理重载前已经耗时 74 秒：新规则下载 1 秒，预检及准备约 7 秒，停止旧后端约 4 秒，后端全量更新与 DNS 处理约 39 秒，核验及缓存约 11 秒，代理规则生成约 10 秒。日志没有完成时间，不能把其余时间全部归因于代理。随后用户测得命中缓存的 `backend ready` 为 0.66 秒，说明重复核验的暖缓存路径正常。

旧链路在预检之后丢弃下载内容，随后 `adblock-fast dl` 强制下载全部启用来源；一份新列表可能下载两遍。上一版批量应用减少了操作次数，但每次仍经过这条完整链路。

## 新操作方式

- **应用并重新加载**：集中处理当前页面的所有待应用选择。有缓存就复用；新增、地址变化或缓存缺失的来源需要下载。选择每个开关时仍不下载、不重载。
- **重新加载**：有草稿时直接执行上面的统一应用；没有草稿时核对当前配置及产物。配置、规则和代理接入没有变化时不重建、不重启。它不是强制重启所有服务。
- **更新订阅**：主动联网获取全部已应用且启用来源。没有草稿时可用；有草稿先应用或撤销。新内容与旧快照相同时复用解析结果，跳过后端重建；内容改变时统一处理一次。

关闭保护时可以先应用规则选择，下次开启生效。保护主开关、临时暂停、误杀放行保留即时行为。未完成恢复、真实外部编辑、陈旧修订或未知任务完成状态仍会阻止新的修改。

## 点击应用后的步骤

1. 取得同一操作锁，核对已运行后端、配置修订、恢复记录和分流选择。
2. 对新增、重新启用或地址/格式变化的来源预检；复用经过内容摘要检查的本地快照，缺失才下载。主动更新则先获取新内容。
3. 保存原配置和批量恢复记录，提交整批选择。
4. 比较有效配置、每个启用来源的内容摘要、当前后端产物摘要。完全相同则跳过重建；否则沿用原生后端处理，但直接复用已有下载内容。
5. 对生成产物做原有严格校验，并同步现有代理适配器。代理输入未变化则不重新生成/重载；变化时仍可能重载 DNS 或代理。
6. 写入完成时间和回执，页面重新核对实际结果，再清空草稿。失败按原有流程恢复，无法确认时保留记录。

## 缓存约束

缓存位于 `/tmp/adzero-source-cache`，目录 0700、文件 0600。URL 通过私有文件计算 SHA-256，不进入缓存文件名、公开任务回执或命令行。正文与解析结果分别校验摘要，缓存损坏、缺失或权限异常时回到原下载/严格解析路径。显式更新前先撤销旧快照证明，避免可选缓存保存失败后错误重放旧版本。

总容量上限为物理内存的八分之一且不超过 96 MB；缓存不足时继续正常下载。单份仍限制 25 MB，最终有效域名仍限制 50 万。缓存不作为持久配置，路由器重启后需要重新准备。

仅在 AdZero 调用后端的子进程 PATH 中提供 curl 交接器，仅识别选中 HTTPS 来源、受支持的参数和原生 `/tmp/adblock-fast_tmp.*` 私有目标。版本/HEAD/其他请求继续交给真实 curl；自定义 curl 参数存在时不重放。不会修改系统 curl、上游脚本或提交后的订阅 URL。非 curl 后端下载器保持原有行为，不能承诺重复下载已消除。

显示名称、校验数量/时间及原生数字 `file_url.size` 不再使代理输入证明失效；有效规则内容和其他配置仍参与核对。缓存命中也不会跳过后端存活和恢复状态检查。

后端原生计划任务可能在 AdZero 之外更新产物。重新加载或关闭前比较产物摘要；发现新产物就撤销旧来源快照证明，避免之后使用旧内容覆盖原生更新。

## 性能边界

首次准备缓存、真正增加规则、规则合并、DNS 重载及代理内核重载仍需要时间。本版没有改写上游规则编译器，也没有缩短代理自身的启动时间。不能仅凭隔离测试承诺用户路由器的新增规则从 100 秒降到固定秒数；需要升级后的完整任务时间线验证。重复加载和更新后内容未变的路径应避免原先的整条重复执行链。

验证结果见 [LOCAL_VALIDATION.md](LOCAL_VALIDATION.md)。下载交接检查使用固定提交的上游 `download()` 函数及真实 OpenWrt shell/ucode/UCI，但网络传输为本地夹具，不等同于真实 HTTPS、完整后端生命周期或真机验收。
