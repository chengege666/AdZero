# v0.17.2 过滤、更新与 DNS 稳定性复查

基线为 v0.17.1。本轮以当前源码、原生 ucode/socket、OpenWrt DNS 和隔离网络命名空间复现问题，没有连接用户路由器。未把历史所有报错归为同一原因。

## 已复现和修复

| 问题 | 修复后的行为 | 验证方式 |
| --- | --- | --- |
| 刷新在下载前作废旧快照凭据；下载失败后，独立重载也失去缓存 | 先下载并检查，失败保留最后一份已验证快照；接受新内容后才作废旧凭据，缓存写失败不会把旧版冒充本次更新 | 原生 UCI/ucode；网络失败、HTML 错误内容、缓存满、内容不变与后续重载 |
| 旧来源自动识别把 HTTP 200 的 HTML 错误页作为未识别的原生格式继续处理 | 明确拒绝 HTML 网页，不把下载成功等同于规则更新成功，旧快照保留 | 旧来源自动格式、CDN 错误网页和配置不变测试 |
| 最近检查复用了内容时间，内容相同时看起来没更新 | 独立保存检查时间，内容时间保持原有含义；元数据变化不触发重复处理 | 原生来源事务及未变化输出复用 |
| 防火墙重载删除增强接管表后，退出流程跳过旧会话清理 | 即使表不存在，仍按私有接管记录清理路由器 53、自有回复源 5354 的 IPv4 DNS 会话 | 实际 nft/conntrack、独立 LAN 客户端，同一 UDP 源端口在崩溃后恢复；原生 11400 会话 ID 不变 |
| 清理失败仍可能丢弃恢复记录 | 接管前持久化意图；失败保留记录并显示退出待确认；外来表、权限错误及不完整记录拒绝假装成功 | 真实删除失败注入；外来表、空选择及重复清理 |
| 只读域名查询持锁也会临时撤下增强过滤 | 核实为私有控制器只读锁时保持入口；变更及未知锁仍退出接管 | 原生 CNAME 过滤跨只读锁持续工作，修改锁出现后撤下并恢复 |
| 增强计时使用了 OpenWrt 24.10 socket 模块不存在的 pair() | 使用两版可用的回环 socket 等待，按实际 poll 事件判断就绪 | 官方 24.10 模块实际计时，25.12 原生入口 |
| 每次增强 TCP 查询重新连接原生 DNS | 同一客户端复用自己的原生 TCP 流；上游关闭时有限重连；错配应答失败，不跨设备共享 | 十二次查询从十二条连接减为一条；短连接上游、短读、流水查询、半关闭及错事务 ID |

## 误拦截与更新边界

- 复查了精确与父域范围、全局放行、临时放行回滚、来源关联、格式解析和 CNAME 决策。新增近似后缀、显式例外、截断及失败应答测试，无关别名和失败应答不记作 CNAME 拦截。
- 基础 Adblock 只接受可等价表达的域名规则，不删掉例外或修饰符后扩大拦截。设备附加放行仍不能覆盖全局或其他插件规则。
- 更新失败仍返回失败，旧缓存只供后续独立操作使用。已接受的新内容无法缓存时，仍走原生下载和最终检查。
- 解析优化只作用于已启用增强入口的 TCP 流，沿用原生缓存与 TTL。十二条连接变一条是隔离传输结果，不是网页加载或公网 DNS 提速倍数。
- 增强入口仍仅接入系统默认或 PassWall 默认 IPv4 LAN 路径，其他代理的基础适配范围不变。

## 验证与局限

488 项原生回归无跳过、274 条 UI 断言、66 项 RPC、5 项文档检查、两版 SDK LuCI Poll、原生采集器和 PassWall/OpenClash DNS 检查、三个 SDK 包与六项 LF/CRLF 安装交付通过。完整记录见 [本版证据](evidence/v0.17.2/validation-summary.json)。隔离测试验证状态机、真实 socket 和 NAT，不能代替用户路由器、原电脑、IPv6、加密 DNS 或特定代理版本的端到端验收。

## 主要修改文件

- `sources.uc`、`source-lib.uc`：刷新事务、检查时间和 HTML 拒绝；`overview.js` 显示最近检查与退出待确认状态。
- `dns-cleanup.uc`、`dns-enhance.uc`：精确会话退出、持久化意图、只读锁识别与计时兼容。
- `dns-io.uc`、`dns-relay.uc`：poll 就绪判断、TCP 连接复用与规则代际退出。
- `tests/test_source_cache.py`、`test_dns_cleanup.py`、`test_dns_enhance.py`、`test_dns_io.py`、`test_dns_relay.py` 和原生网络检查脚本：新增回归与真实网络证明；`build_ipk.py` 纳入新增模块。
- `README.md`、在线文档、版本与安装脚本：同步 v0.17.2 和实际使用边界。没有新增大型依赖，没有修改用户路由器配置。

参考 [RFC 7766 连接复用](https://www.rfc-editor.org/rfc/rfc7766.html#section-6.2.1) 和 [ucode socket API](https://ucode-lang.org/ucode/module-socket.html)，并以发行版实际模块验证差异。
