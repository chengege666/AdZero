# v0.18.0 逻辑、界面与代理兼容复查

基线为 v0.17.2。本轮检查控制器串行事务、代理选择、原生服务启动、规则快照、界面轮询、未提交编辑和退出恢复。没有连接用户路由器，也没有把模拟界面、SDK 构建或新连接查询记成现网认证。

## 修复的实际问题

| 问题 | 修改 | 验证 |
| --- | --- | --- |
| PassWall 已使用外部期限，但其他代理及系统 DNS 仍使用 ucode 内部定时启动 | 服务重载统一走既有 coreutils-timeout；缺少工具时在配置修改前拒绝应用；恢复时仍不启动用户已停止的代理 | 原生 OpenWrt 25.12.5 / ash 中，旧版系统 DNS 应用和恢复两次读取到 SIGCHLD 阻塞位 65536，新版均为 0；另有真实 OpenClash DNS 与事务回归 |
| 非 procd 管理的插件可能只凭保存的启用选项被当作正在运行；共用内核易产生误判 | 一次扫描进程配置归属，区分 PassWall / PassWall 2、OpenClash / Nikki、HomeProxy 客户端；校验、版本查询不算活动代理 | shell 管理、共享内核、未知目录、相似前缀、已停止内核和旧 PassWall 客户端测试；探测不写 UCI，不输出 argv |
| 输入中发生状态重绘会丢焦点和选区 | 重绘保留输入位置；未暂存的 DNS 编辑也加入离页提示；退出释放轮询与历史/离页监听 | 生产视图的真实属性语义、输入选区、离页监听和原生 SDK Poll 回归 |
| 上一轮挂载的异步采集回执仍可能改写新挂载状态 | 给采集和增强状态请求绑定页面代际，忽略旧请求 | 延迟旧回执，重新挂载并先取得新数据，再释放旧回执，确认新数据不被覆盖 |
| 选中检测命令后，等待状态的进度也停止更新 | 命令区保持原 DOM，仅更新检测状态、按钮和进度；最终回执仍正常展示 | 保留命令选择的同时等待/通过两种回执回归；浏览器交互复核 |
| 页面按钮允许尝试当前明确不支持的代理接入 | 开启条件与提示共用一套前置判断；接入详情区分识别、可适配和已接入 | PassWall 2 明确为检测范围时，在任何修改前显示原因；关闭与恢复入口不因此封死 |
| 新增写操作已持锁，但状态接口漏报活动任务 | 补齐临时放行、到期恢复、增强保存和备用 DNS 切换的操作白名单，界面显示具体动作 | 四种真实进程身份的锁记录从旧版 active=false 复现为新版 active=true；不暴露 PID，也不接受未知/失效锁 |
| 增强页首次读取失败后，后台恢复只刷新不存在的状态节点 | 后台恢复同时显示新编辑器；读取失败标记上次状态，保留编辑；同一挂载的重叠读取共享请求 | 初次失败、后台恢复、重复请求与旧代际回执回归 |

## 界面设计

- 四页统一导航、标题、表单和操作层级。导航使用真实链接，可收藏具体菜单，支持前进/后退；未知 LuCI 锚点不重置菜单。
- 概览保留保护状态和四个真实指标，效果检测、接入详情和 DNS 设置分组呈现；不把所有安装过的插件展开堆在首页。
- 规则页保留批量暂存和一次应用。访问控制去掉重复标题，域名查询、自定义名单与最近拦截分别成组；增强入口与上游测试的用途分开说明。
- 浅色/深色沿用同一组设计变量；适配 360px 手机视口，调整导航触控、长数字和社区链接，补足占位文字、键盘焦点与跳转入口。
- 沿用 LuCI 原生 DOM、现有本地图标和 CSS 动效，无新增框架、字体下载或运行依赖。浏览器使用生产视图和原生 DOM，RPC 与网络数据为明确模拟。

## 兼容边界

基础适配仍为 NaiLink、PassWall、OpenClash、Nikki、SSR Plus+。本版改善这些路径的运行识别、服务启动与故障前置判断；PassWall 2、HomeProxy 的运行识别更准确，但仍不自动修改其 DNS。识别数量不等于适配数量。

PassWall 扩展核对旧版 V2Ray、Shadowsocks、Trojan、Hysteria2、TUIC 等客户端的配置归属。未知目录不猜测，遇到真实多代理也不随意选择。NaiLink 管理服务与实际 dae 内核继续分开核对。原生 DNS 模式、代理节点和已有恢复规则不改。

对新接入点先核对原生扩展接口。例如固定版本的 [PassWall 2 Xray 生成器](https://github.com/Openwrt-Passwall/openwrt-passwall2/blob/0f923be3f00f9fb8db9591c9ecab41e7de5ec75e/luci-app-passwall2/luasrc/passwall2/util_xray.lua#L1514) 明确跳过 ext 规则，不能直接套用其他插件的文件型规则接口。未通过原生生成、回滚和 DNS 证据前，不把它标成已支持。

## 验证记录

最终源码摘要、回归、RPC、原生 DNS、安装交付和 SDK 记录保存在 [evidence/v0.18.0](evidence/v0.18.0/)。原生服务的反例和正例分别保留，不把主机 shell 的检查代替 OpenWrt ash。

补跑旧 NaiLink 网关检查时，原夹具的合成 `/proc` 没有为控制器提供进程身份，导致测试先于目标授权检查退出。验证脚本改为在放行控制器前映射该真实子进程的 stat；后面的重载身份测试仍使用合成数据，不把真实宿主 `/proc` 挂进去，也不改产品控制器的身份核对。

本版未测量公网提速倍数或整体广告拦截率。路由器、原电脑、特定代理版本、TUN、IPv6 和加密 DNS 仍需要设备验收；不会远程清除客户端已有缓存。

界面核对参考 [Vercel Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines/blob/main/command.md)，并以现有 LuCI 的宿主主题、键盘行为和手机显示为准。

## 主要修改文件

- `adapter.uc`：统一服务重载期限与前置依赖检查。
- `proxy-state.uc`、`probe.uc`：进程配置归属和公开运行证据。
- `overview.js`、`overview.css`：四页界面、导航、接入详情、输入保护、检测进度与异步请求代际。
- `tests/test_probe.py`、`test_adapters.py`、`test_routing.py`、`test_view.cjs` 和 `check_service_spawn_runtime.py`：针对性回归与原生信号验证；OpenClash 原生测试补齐已声明的 timeout 依赖。
- README、兼容矩阵、代理切换说明与在线文档：同步实际功能和边界。
