# 过滤规则管理

「运行概览」处理日常开关、暂停和误杀排查；「过滤规则」管理订阅。预置规则库只是快捷入口，用户也可以添加符合格式的自定义 HTTPS 来源。列表显示名称、地址、启用状态、下载校验后的数量和最近校验时间。删除订阅需要在该行确认，个人放行名单不受影响。

## 支持格式

| 格式 | 示例 | 约束 |
| --- | --- | --- |
| 域名列表 | `ads.example.com` | 每行一个 ASCII/punycode 域名，支持注释和空行 |
| Hosts | `0.0.0.0 ads.example.com` | 每行一个域名映射，支持常见本机头部；不接受复杂别名 |
| 基础 DNS Adblock | `\|\|ads.example.com^` | 只接受这种基础域名语法和注释；高级例外、修饰符、正则及网页元素规则会拒绝整份导入 |

域名不接受 IP、下划线和通配符。订阅地址只接受 HTTPS 的标准端口，不接受账号密码或片段；查询参数可以包含订阅令牌，地址仅保留在路由器配置中，不写入浏览器概览快照或任务回执。每份最多 25 MB / 50 万域名，最多管理 30 个拦截订阅；已知格式的启用列表合并后最多 50 万域名。既有后端其他格式保留原行为，不会伪装成已通过上述导入校验。

规则库包括 HaGeZi Light / Normal / Pro、anti-AD 和 AdAway。来源链接指向各自维护项目，列表内容会随上游变化；选择和使用需遵守对应规则许可。每项的数量可能重叠，合并去重及个人放行后，以概览有效域名数为准。相同系列通常选一项即可，叠加会增加下载、处理和内存成本。

## 应用与恢复

添加、开关、删除和更新均在控制器现有全局锁下执行。先用严格验证证书的 curl 校验所有已知格式的启用来源，再提交实际 adblock-fast file_url 配置；开启状态重新下载/处理，并通过现有适配器同步到当前代理。后端会再次下载，预检内容不是固定不变的本地快照。最终仍检查后端实际产物与代理应用结果。

失败时按日志恢复旧配置并尝试重建旧规则。恢复只在配置与操作前或操作后模型一致时执行，忽略上游写入的数字 size 元数据；检测到其他工具的并发修改则停止恢复，保留记录供关闭并恢复。请不要手动删除 `/etc/adzero/sources-pending.json`、临时操作锁或其他恢复文件。

v0.8.1 比较匿名节的顺序与内容，忽略 libuci 删除后自动重新生成的标识；命名节仍核对实际标识。每次操作仍用显示的标识和 URL 共同核对目标，旧编号指向其他来源时拒绝修改。有其他页面未提交的后端 UCI 修改时，先在原页面保存或撤销，不让订阅变更顺带提交或丢弃这些内容。

明确选择的订阅保留在后端配置，关闭保护、标准升级和卸载不会把这些个人选择恢复为初次安装默认值。关闭时仍恢复 AdZero 自管的 DNS/TLS/代理入口。保护关闭时可以管理订阅，主开关不会因此自动开启；下次开启强制重建，避免沿用旧缓存。保护开启且没有手工拦截域名时，至少保留一个启用的订阅；需要暂停全部过滤时用临时暂停或主开关。暂停、外部托管或未完成恢复时禁止改订阅。

规则操作通过带类型的 RPC 提交给短任务启动器；慢操作在后台执行，不占住浏览器请求或 rpcd 主循环。前端持有随机任务回执，每两秒只读查询完成结果，再核对真实状态和配置。回执不包含日志、URL 或任意命令参数。重启会清空临时任务回执，持久恢复日志仍保留；状态不明时重新检测，不要重复提交。

## 返回菜单

概览快照只供展示，有效期 5 分钟，按 LuCI 登录会话隔离在当前标签页的 sessionStorage。返回时先展示上次概览，并后台重新读取；确认之前锁定修改。失败保留旧概览及重试入口，不将旧状态当作当前运行结果。首次打开、快照损坏或过期、重新登录以及禁用浏览器存储时，都可走正常实时读取路径。

规则列表不写入快照；打开规则页会重新核对列表，但已有行保留显示，核对前禁用编辑。浏览器中保存的源地址只在当前页面内存和输入框中，离开页面不持久保存这些内容。当前版本不提供流量日志、按订阅命中次数、编辑订阅 URL 或全部 AdGuard Home 过滤语法。
