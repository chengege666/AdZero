# 实用功能评估（2026-10-21）

评估基线为 v0.6.3。v0.7.0 已交付下文两项 P0：域名查询/范围放行/撤销，以及 5/15/30 分钟临时暂停。共享范围放行在界面明确显示含子域；个人名单与原后端白名单分开保存，暂停撤销四代理的自有入口。四代理隔离联动通过，新功能仍需真机验收。以下保留原始缺口评估；P1/P2 仍为建议。

## 现有能力与缺口

| 项目 | 当前实现 | 日常使用的缺口 |
| --- | --- | --- |
| 开关与恢复 | ctl 启停、备份、所有权和错误恢复；界面读取实际结果 | 没有带倒计时的临时暂停 |
| 规则 | 准备默认轻量源，沿用已有源，手动更新，拒绝空/无效导出 | 没有规则档位、上次成功更新时间、来源索引或用户可选历史版本 |
| 多代理接入 | NaiLink、PassWall、OpenClash、Nikki 的规则同步与恢复 | 缺少统一的误杀放行策略和效果查询入口 |
| 状态 | 真实有效域名数、当前接入、后端检查 | 域名数不是拦截次数；没有查询日志、设备级计数或终端链路证明 |
| 名单 | 上游支持 allowed_domain / blocked_domain，AdZero 暂无编辑入口 | 子域放行与父域拦截重叠时，当前适配器会拒绝，避免误改语义 |

依据：`ctl` 的 status/enable/disable/refresh/reconcile 入口、`watch` 的同步循环、`adapter-lib.uc` 的导出和例外检查、LuCI ACL 及视图。移除显示区不会删除这些后端保护。

## 建议顺序

| 优先级 | 功能 | 用户能完成的事 | 必须满足的条件 |
| --- | --- | --- | --- |
| P0 | 域名查询与误杀放行 | 网站登录、支付或视频异常时，查询域名，确认命中后放行，并支持撤销 | 区分精确/父域命中；统一四种代理的允许例外；同步失败回滚；不能把“在规则中”当成“终端请求已经被拦截” |
| P0 | 临时暂停 5/15/30 分钟 | 临时排障后自动恢复，减少忘记重新开启 | 同时移除代理侧自有拦截入口；明确剩余时间；手动关闭取消恢复；恢复前重查所有权和代理变化；确定重启与时钟异常策略 |
| P1 | 精选规则档位 | 在轻量、均衡、强力之间选择，知道各自覆盖范围及误杀风险 | 明确规则来源与许可；共享去重结果；保留个人放行；应用前校验资源预算和导出语义，失败恢复旧规则 |
| P1 | 更新记录和规则回退 | 看上次成功更新时间、更新结果和规则变化；出问题时回到上个有效版本 | 记录当前真正使用的规则哈希；下载失败仍使用有效旧版；只恢复本插件持有的快照，不能覆盖用户并发修改 |
| P1 | 终端验证助手 | 用正常域名和拦截样本检查当前设备，发现浏览器安全 DNS 或 IPv6 路径未经过过滤的情况 | 路由器本机查询与 LAN 终端查询分开；无法判断时显示未知；不因配置已同步就自动勾选“终端已验证” |
| P2 | 可选查询记录、设备例外 | 找最近被拦截的请求，定位特定电视/手机问题 | 先确认各代理提供的查询事件和客户端标识；本地存储有容量/保留期限制；统计必须写明覆盖范围，不能跨链路重复计数 |

优先交付“查因 → 放行 → 复查”和临时暂停，再扩展规则档位与更新管理。查询日志和设备策略要等共同的数据与策略模型明确后推进。

## 两处不能直接照搬的实现

1. **暂停需要覆盖整个接入路径。** 只调用 adblock-fast 的 pause，不会自动撤销 NaiLink GeoSite、PassWall 列表、OpenClash 覆写或 Nikki 混入中的自有拒绝规则。需要由 AdZero 的同一把操作锁与恢复记录协调。上游当前文档的 pause_timeout 范围为 1–600 秒，实际固件版本还需检查；15/30 分钟不能直接假定受支持。
2. **白名单需要处理例外优先级。** 当前 domains() 遇到“父域被拦截、子域允许”的重叠会拒绝导出。直接加文本框写 UCI，会出现后端允许而代理继续拒绝的情况。先明确“仅此域名 / 包含子域”的语义，并在四种代理上验证；无法等价表达时阻止应用并解释原因。

域名查询第一版可以说明命中当前有效规则。合并去重后的文件通常不保留原订阅来源，因此“命中哪条订阅”需要更新时建立来源索引，不能凭域名猜测。订阅凭据不得进入查询结果或诊断导出。

## 首页方向

首页继续保留开关、过滤状态和常用操作。临时暂停放在开关附近，域名查询与误杀恢复放在独立实用卡片；规则详情按需展开。新增功能必须已有可验证的后端能力，避免添加只能演示的控件。

DNS 层适合拦截独立广告/跟踪域名。视频与广告共用域名、网页占位和页面元素清理属于其他能力范围；浏览器协作可另行评估，不能通过扩大 DNS 黑名单承诺解决。
