# v0.19.1：DNS 应用预检与单一配置入口

PassWall 使用 Xray／sing-box DNS 时，国外组并发在 v0.19.0 会到适配阶段才拒绝并回滚。v0.19.1 在编辑时说明组合限制，并在修改配置、处理规则和重载网络之前再次执行后端预检。保留原引擎和节点，不通过切换引擎绕过限制。

## 功能与界面

- 运行概览的「DNS 与分流」统一管理地址、查询策略、严格模式、SOCKS5 端口、自动备用和上游测试。DNS 增强页移除“上游与备用”，保留 CNAME 与设备附加规则，减少重复入口。
- 不支持的 PassWall 国外并发、缺少 SOCKS5 端口或 SOCKS 路径不可用，显示可操作的原因；浏览器与后端分别校验。代理状态变化后，应用时重新检查，保留未应用草稿。
- 自动备用随 DNS 草稿统一应用；兼容旧增强页保存的设置。只改备用开关时更新后台监测，不重载正常工作的代理。并发组不做备用轮换。
- 提供各代理的起始设置、SOCKS5 端口查找说明。测试只针对已应用配置，未应用修改存在时不能测试旧设置并误认为新设置已生效。

## 关键文件

- `adapter.uc`、`ctl`、`progress-lib.uc`：只读 DNS 计划预检、原因码、白名单化的 PassWall DNS 模式状态。
- `routing-lib.uc`、`sources.uc`、`dns-enhance.uc`、`/etc/init.d/adzero`：统一备用偏好、旧配置兼容与监测进程更新。
- `overview.js`、`overview.css`：统一编辑器、即时限制提示、测试区与紧凑增强布局；后台读取不会丢弃当前表单绑定。
- `DNS_SETTINGS.md` 与在线文档 DNS／增强页：推荐设置、端口位置、测试步骤和保护范围。

## 验证与边界

验证结果保存在 [测试摘要](evidence/v0.19.1/summary.json)：532 项 Python 测试、340 项界面回归断言、原生 rpcd 和代理运行检查，以及三个官方 SDK 目标的构建与包内容核对。另检查六组安装器交付流程，覆盖 LF／CRLF。

新事务回归核对：不支持的 PassWall 组合在预检失败后，AdZero 配置、PassWall 配置、恢复记录及重启次数均保持原值；自动备用单独修改不触发代理重载；新设置中的显式关闭优先于旧设置中的开启。

桌面浏览器使用实际 LuCI DOM 与模拟 RPC，完成“修改 → 一次应用 → 同页测试”；360 像素手机视口完成表单布局检查。没有连接或修改用户路由器，未把隔离上游、服务夹具或手机布局检查算作真实网络与终端验收。

发行目标为 OpenWrt 24.10.8 x86/64 IPK、25.12.5 x86/64 APK、25.12.5 rockchip/armv8 APK。没有新增运行依赖。严格模式仍限定已管理的默认 IPv4 LAN DNS 路径；浏览器／应用 DoH 与其他 VLAN 等范围见 [DNS 设置](DNS_SETTINGS.md#严格-dns-防旁路的范围)。
