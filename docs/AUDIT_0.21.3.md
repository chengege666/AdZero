# v0.21.3 并发 DNS 传输路径审计

## 只读实机证据

检查时路由器为 v0.21.2，唯一活动代理 NaiLink，当前两组均为单一模式、严格关闭、未配置本机 SOCKS；当前过滤后端正常。没有强制切回用户此前的故障配置，不能称为完整复现历史断网。

两个国内上游 UDP DNS 均在约 6 ms 返回有效应答。普通诊断进程对两个国内与两个国外上游的 TCP 53 连接均未在 2 秒内完成；其中三个相同 IP 的 TCP 443 可连接。443 结果仅表示连接，不是 TLS 或网页验收。此证据确认当前独立进程的所选 TCP 53 路径不可用，不能据此唯一归因于运营商、内核规则或订阅节点。

随后仅把新预检函数经标准输入交给路由器 ucode，调用已安装的 I/O 库，在进程内构造候选设置。单一策略无需共享池检查；双并发且无 SOCKS 被明确拒绝；国内并发被实际 TCP 检查拒绝。没有保存候选设置、安装文件或切入故障路径。这验证了预检能识别当前条件，不是新版完整部署或并发联网验收。公开回执见[只读候选检查](evidence/v0.21.3/router-readonly-preflight.json)。

## 源码结论与修复

NaiLink 内部 DNS 自行选择出口；AdZero 的独立池使用普通 TCP 套接字，不继承内核内部 DNS 路由上下文。原代码在无 SOCKS 时允许国外普通 TCP，并只核对健康记录／监听，未核对真实应答。国内测速又仅测 UDP，易把两条不同路径混为一谈。

| 位置 | 改动 |
| --- | --- |
| `dns-pool-state.uc` / `dns-pool.uc` | 对候选配置执行只读 TCP／SOCKS 上游预检；监听启动和复用后经本机入口核对应答。公共测试域名须获得匹配、完整且含答案的 NOERROR；NXDOMAIN、空答案、SERVFAIL 或截断包均不确认健康。 |
| `adapter.uc` / `progress-lib.uc` | 新计划的 SOCKS 端口传给预检；NaiLink 国外并发明确要求本机 SOCKS。分开报告国内 TCP、国外代理 DNS、启动与监听问题，保留事务和恢复记录。 |
| `dns-io.uc` / `dns-enhance.uc` / `overview.js` | 测试国内实际传输，显示 TCP / UDP；旧代理／引擎的结果失效；前端与后端使用一致的 SOCKS 前提。 |
| 在线文档与 DNS 设置说明 | 更正 NaiLink 起始建议，说明 PassWall 同类风险与 OpenClash / Nikki 原生路径的区别。 |

普通 TCP 成功不等于抗污染；国内使用 www.baidu.com、国外使用 www.google.com 进行有界 DNS 查询，避免本地合成 .invalid 应答冒充上游就绪，不进行网站登录判断。并发组只要求至少一个有效上游，不跨组借用应答。没有实现猜测性的套接字标记绕过，也不切换到可能回环的 UDP 上游。

## 验证范围

新增原生 ucode 策略测试，覆盖四代理模式、候选 SOCKS、缺失出口、错误应答和不跨组回落。私有网络命名空间实际启动生产池与原生 ucode，验证 UDP 正常但 TCP 不通、入口就绪但 SERVFAIL、SOCKS DNS 失败、复用入口后上游失效、以及预检不改 UCI／所有权标记。

完整原生检查、三套官方 SDK、安装交付与 GitHub 检查计数见[同源码验证摘要](evidence/v0.21.3/summary.json)。OpenClash / PassWall 原生集成与 NaiLink 管理接口检查使用隔离夹具；NaiLink eBPF 真实出口和各插件公网终端仍需设备验收。本轮仅对用户设备执行只读状态及有界网络探测，没有应用、重启、切换、清连接或升级。
