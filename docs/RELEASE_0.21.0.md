# v0.21.0 — 设备容量分档与 DNS 连接复用

修复固定 50 万最终规则限制对大内存设备过严的问题，并补齐大规则恢复、DNS 并发连接和代理切换重试。

- 每个订阅独立检查大小、格式和数量；合并时精确去重，按原生语义估算父域优化与已知放行后的数量。按总内存分档，至少 3 GiB 的设备单来源最多 200 万、最终有效域名最多 400 万。不是累计启用配额，也不会让分批开启绕过最终资源保护。页面区分单来源上限、最终上限和最近预检数量，保留真实配置冲突保护。详见[规则与容量](RULE_SOURCES.md)。
- 大规则和原始文件的恢复内容改存私有摘要快照，避免把整份数据反复写进恢复 JSON。核对快照完整性、实际文件与外部改动，旧版内嵌记录仍可恢复；失败继续保留恢复资料。成功后清理无引用快照。
- 并发 DNS 短时复用组内 TCP／SOCKS 连接，避免每次查询重新握手。连接按组、上游和 SOCKS 端口隔离，限制数量和寿命；失效连接在原截止时间内只重连一次。没有增加答案缓存，不改 TTL 或国外出口，不把错误响应当作可重试成功。
- 代理切换后台同步锁忙时返回专用临时状态，不再误报成功；下一轮重试。实际适配失败延后一分钟再试，避免连续重载；保持已有的多代理冲突识别和操作锁。

规则源不因更新而自动全选；保留现有 DNS、节点与严格模式选择。建议一份主规则加必要补充，避免只追求数量而增加误拦截。DNS 过滤仍无法覆盖同域视频广告、网页占位及绕过路由器的加密 DNS。

本地验证通过 601 项 Python 测试、374 项界面断言、5 项文档测试、68 项实际 RPC 检查、OpenClash／PassWall 原生启动检查，以及三个官方 SDK 的构建和每包 62 项载荷核对。发行包通过 6 项安装器交付检查；400 万条真实 Mihomo 规则通过 16 项 DNS 对照，另有 40 项放行／暂停／恢复与 Fake-IP 回归。

验证记录见[发行验证摘要](evidence/v0.21.0/summary.json)，修改位置与边界见[审计说明](AUDIT_0.21.0.md)。百万级测量属于开发机机制与容量验证，不等于路由器速度或实机验收。开发期间未连接、修改或重启用户路由器，没有新增运行依赖。
