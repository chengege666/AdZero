# v0.21.3 — 并发 DNS 实际路径检查

NaiLink 原生 DNS 可用，不代表独立并发进程的普通 TCP 53 上游可达。旧版只确认并发入口启动，可能把无法获得应答的入口接入网络；此前“无 SOCKS 也可使用 NaiLink 两组并发”的建议缺少出口条件，现已更正。

- 应用前检查新计划的国内 TCP 与国外 SOCKS DNS，失败不切入新路径；入口启动、复用及代理重载后再次核对应答。
- NaiLink 国外并发和严格模式要求可用本机无认证 SOCKS5。没有该出口时先用两组单一＋备用；不猜端口，不把透明代理端口当作 SOCKS。
- PassWall 共用国内 TCP 并发路径，加入相同检查；国外并发仍要求原生 TCP DNS 与 SOCKS。保留 Xray / sing-box 引擎与真实冲突保护。
- OpenClash / Nikki 继续使用原生内核并发，不新增本机 SOCKS 要求。
- 国内测速按已接入模式使用 TCP 或 UDP，显示实际传输；切换代理后旧结果需重测。在线文档同步更新注意事项与推荐起始设置。

不自动改成 UDP、降级查询策略、替换节点或把国外查询回落直连。升级保留用户设置，严格模式仍按原有阻断和恢复规则处理失败。无新增运行依赖。

详见[诊断与验证边界](AUDIT_0.21.3.md)、[验证摘要](evidence/v0.21.3/summary.json)及[在线 DNS 文档](https://slobys.github.io/AdZero/dns.html#compatibility)。本轮没有修改或升级用户路由器；隔离测试不代替实机启停与公网终端验收。
