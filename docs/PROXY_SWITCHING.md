# 切换代理

AdZero 自动接入 NaiLink、PassWall、OpenClash、Nikki，并提供 SSR Plus+ 原生广告过滤接入。先停止旧代理，再启动新代理，最后在 AdZero 点击「重新检测」。保护开启时，后台也会定期核对变化，通常在一分钟内尝试同步。

v0.15.3 区分“后台仍在切换”和“切换失败”。后台操作持锁且进程身份核对通过时，显示“正在同步代理接入”，暂时不提交关闭、重新加载或应用；完成后自动更新页面。不会再把正在恢复旧插件的中间状态直接当成需要人工关闭的故障。页面可见时每五个轮询周期核对一次，活动操作最多核对六十次，超时仍可手动重新检测；不会抢锁、杀进程或删除锁。

如果恰好在同步开始前点击关闭，仍可能遇到锁竞争。锁等待超时表示**这次关闭没有执行**，页面会显示“上次关闭未执行”，下面显示实际保护状态，不自动重试关闭。同步完成后若仍需要关闭，再点击一次即可；点击“重新检测”可清除旧操作提示。真实恢复错误继续保留恢复入口。锁目录存在但进程已退出、身份不符、记录缺失或过旧时，不会伪装成仍在同步。

先开新代理、再关旧代理的短暂重叠期间，仍不会从两个活动代理中随意选择一个。只保留一个代理后，后台会再次核对；如果不能恢复旧插件的配置，仍保留恢复记录。本次不改变代理选择、DNS 或分流规则。

NaiLink 的管理服务可以一直运行，而代理内核已经停止。AdZero 现在查询实际内核状态，不再仅凭管理进程或保存的启用选项判定它正在代理。PassWall 不要求必须注册 procd 实例；其配置启用状态仍可作为识别依据。共享的 Xray、Mihomo 进程不会随意归给某个插件。

如果提示多个代理，会列出识别到的插件；如果查询失败，会提示无法确认内核状态，而不是误报为同时运行。只需检查对应插件后重新检测，切勿删除恢复记录。

切换时会先恢复旧插件中 AdZero 管理的设置，再接入新插件。已确认停止的旧代理不会被重新拉起。若旧插件的管理接口完全不可用，恢复可能仍需先让该接口可访问；AdZero 会保留记录并说明失败，不会丢弃原设置。

PassWall 2、HomeProxy 目前仅识别。SSR Plus+ 接入原生 `/etc/ssrplus/deny.list`，保留节点、DNS 上游和分流策略；使用它时请先关闭 AdZero 自动分流。恢复只移除 AdZero 标记块，保留原有列表和后来添加的用户域名。

SSR Plus+ 的活动判断检查其自有客户端进程路径或配置参数，不把保存的节点选择、DNS 辅助程序、服务端或其他插件的共享 Xray 进程当成它正在代理。

v0.14.0 修正 rc.common 启动脚本的调用方式。PassWall 和 SSR Plus+ 会进一步核对实际 DNS 进程、配置包含路径及三个规则样本；尚未加载时最多立即重试一次，失败后间隔至少五分钟，连续三批仍失败则等待人工重新加载。手动重新加载或改变规则可重新尝试，不强制下载全部订阅。已停止的旧代理不会被拉起。

这些检查确认配置链路，实际 LAN、IPv6 网络、用户 ACL、加密 DNS 绕过和节点出口仍需设备验收。不同插件的原生接口分别适配，不根据共享内核猜测插件所有者。

v0.15.2 修复“点击关闭并恢复后仍提示未完成，刷新页面却已经关闭”的状态确认缺口。任务成功后若读到恢复中的状态，会先做四次间隔一秒的复查；仍未确认时提示继续核对。页面可见时每五个轮询周期检查一次主状态，恢复异常最多检查十二次，之后停止自动检查并保留“重新检测”。检测到统计快照中的接入已经变化或保护已停止，也会核对主状态。

上述自动确认只读取状态，不重复关闭、启用或重载。确认期间主开关显示“正在确认”，防止重复提交，仍可点击“重新检测”；自动确认超时后恢复手动操作入口。确认已关闭后即可再次开启，无需刷新整页；任务明确报错、状态最终与请求不一致或恢复持续失败时仍会提示错误。隐藏页面暂停轮询，离页后丢弃迟到回复；旧的后台回复不会覆盖较新的手动检测结果或缓存。切换事务本身仍按原有逻辑恢复旧插件并接入新插件，不丢弃恢复记录。

本轮隔离测试覆盖管理服务运行但内核关闭、切换 PassWall、真实多代理冲突、API 无法访问、恢复时不启动旧代理，以及开关自动分流的两种切换路径。实际路由器的切换仍需现场确认。

v0.13.0 的首页接入卡片跟随轻量统计快照更新，后台同步结束后会显示当前已接入的插件；检测到代理、配置已同步和终端检测通过仍是三个不同层次。拦截量不增长时先做终端查询对照，不把普通查询强行算为拦截。
