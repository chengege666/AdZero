# v0.21.1 — 修复 DNS 并发入口启动误判

v0.20.5 和 v0.21.0 的并发入口等待使用外部 `sleep 0.1`。部分 OpenWrt BusyBox 没有启用小数秒支持，30 次等待立即失败，导致正常的异步启动被提前判定为失败。用户交接包的 4 次任务日志与该路径吻合；在隔离环境中也复现了同一函数的问题。

- 改为 ucode 原生毫秒等待和单调时钟截止时间，保留三秒就绪预算及最后一次检查，不依赖 BusyBox 小数秒功能。
- 继续核对健康记录的文件类型、所有者、权限、大小、配置签名和新鲜度；新记录增加进程身份。旧失败记录不会立即中止下一次启动，记录缺失或无效时仍拒绝接入。
- 区分启动请求失败、未就绪、配置不符、陈旧／无效记录、进程无法确认、监听和运行失败。仅向页面传递固定原因，不暴露代理配置。
- 页面区分“本次操作已撤销，原配置已恢复”与“恢复尚未确认”。保护关闭时，效果检测提示先开启保护。

规则容量、DNS 地址、并发选择、严格模式和代理节点沿用现有配置；修复无需关闭并发或严格模式。详见[审计与验证](AUDIT_0.21.1.md)及[验证摘要](evidence/v0.21.1/summary.json)。开发期间没有连接、修改或重启用户路由器；隔离验证不等于实机 LAN 或 Windows ChatGPT／Codex 验收。
