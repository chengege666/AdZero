# v0.20.2 — 缓存容量预检与后端失败诊断

修复规则应用流程中一个可重复的预检缺口：复用缓存数量摘要或只检查新增列表时，原有列表与新列表的合计容量可能没有被完整计入，导致进入后端重建阶段后才被最终检查拒绝。

## 变化

- 对有可验证快照的启用列表合并实际域名，包含未修改的列表；复用摘要仍检查域名集合。超过 50 万时在提交配置和停止后端前拒绝应用。
- 按实际域名去重，不直接相加列表数量；两份大量重叠的列表仍可通过。已校验的解析缓存损坏时，可从经过摘要验证的原始快照离线重解析，不为容量检查重新下载未修改的列表。
- 保留原生旧格式兼容路径：没有可验证快照或不能独立识别的旧格式仍由原有后端检查把关，预检不伪造结果。单文件及输出 25 MB、单列表和结果 50 万域名上限不变。
- 后端状态仅发布白名单错误代码，不返回私密 URL、文件内容或错误附带信息；任务回执区分容量、下载、内存、DNS 重载、规则处理和输出文件问题。
- 明确区分“任务失败”和“保护停止”。失败后若重新读取的状态为接入已配置、后端就绪，显示“本次规则操作未完成，当前保护仍在运行”；草稿保留，不声称这批规则已应用。

## 修改文件

`sources.uc`：缓存与未修改列表的合计预检；`backend.uc`、`adapter-lib.uc`：只读检查及明确错误分类；`ctl`、`progress-lib.uc`：在恢复前保留首个固定失败原因；`overview.js`：任务与保护状态分开显示。相应增加批量事务、后端诊断及界面回归测试，并同步在线文档。

通过 567 项 Python 测试、348 项界面断言及 5 项文档测试；RPC、OpenClash 与 PassWall 隔离运行检查通过。三个官方 SDK 目标完成构建，每包核对 59 项载荷文件，并用发行包完成 6 项安装器交付检查。源码摘要与三个构建一致，详见[验证记录](evidence/v0.20.2/summary.json)。

新增回归先在 v0.20.1 上复现缓存合计遗漏，再验证修复后在停止后端前拒绝超限；覆盖大量重叠列表、缓存损坏的离线回退、新旧列表混合，以及后端失败后成功恢复仍保留最初原因。

用户提供的当前状态为 OpenClash 接入已配置、后端就绪、246,924 条规则；最近两项任务返回成功。这些是当前配置与后端状态，不能证明截图中那次失败的历史原因，也不等于终端过滤效果已经验收。未操作用户路由器，不把本地回归当作实机验收，也不自动删除或停用用户选择的列表。
