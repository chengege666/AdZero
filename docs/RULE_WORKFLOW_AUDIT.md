# v0.10.4 规则校验与更新流程检查

本轮覆盖 AdZero 规则库和 adblock-fast 1.2.4-r4 原始配置中的 21 个 HTTPS 订阅地址，包含域名列表、Hosts、基础 DNS Adblock，以及新增、启停、编辑、删除、更新、重新加载和批量应用。没有引入新的 DNS 引擎或大型依赖。

## 校验在做什么

校验只读取文件并检查格式、域名语法、数量和大小限制，最后核对后端产物。**不会逐个访问列表中的网站，也不会逐域名发 DNS 查询或测速**。下载时正常验证 HTTPS 证书，以免把下载错误页、损坏文件或不支持的过滤语法交给 DNS 后端。

AdGuard Home 同样会下载和解析过滤列表，比较内容校验值，只在列表变化后更新过滤引擎；已有列表可以从本地加载。可参阅其 [过滤列表流程](https://github.com/AdguardTeam/AdGuardHome/blob/master/internal/filtering/filter.go)。AdZero 当前通过 adblock-fast 生成 DNS 产物，并将变化后的规则同步到代理，所以真实变更可能包含 DNS 处理和代理重载。不能将用户之前看到的百秒耗时简单归因于校验，也不能由开发机夹具耗时推断路由器速度。

## 本次修复

1. **格式兼容统一检查**：Hosts 和基础 Adblock 的下划线记录会被原生 ASCII 处理丢弃，现在记录排除数；已知系统头部可包含多个本机别名。Hosts 中原生不加载的单标签、IPv6 映射和含 `localhost` 的行不再计入可用规则。StevenBlack 的原生头部区间处理也保持一致。
2. **旧原生域名格式**：精确的 `*.domain` 条目按原生行为排除并计数，绝不去掉前缀后扩大成父域拦截。新建自定义域名导入仍拒绝通配符；例外、修饰符、正则、网页元素及复杂 Hosts 广告别名仍拒绝，不通过删语法拼出域名。
3. **相同内容复用**：主动更新仍检查网络内容，但正文相同且解析证明有效时，只恢复小份证明文件，不再重写整个正文和解析数组。即使可选缓存预算已满，也不会因此丢掉相同正文的有效证明。缓存损坏、证明版本变化或实际内容变化时重新检查。
   对域名及基础 Adblock，在同时核对当前产物、有效配置和完整解析证明后，注释、时间头部、顺序、大小写变化也不再触发全量重建。Hosts 保留字节比较，因为其原生处理存在与头部、注释相关的行为，不能一概忽略。尾点域名按后端真实能力处理，防止规范化后的字符串相同而实际规则不同。
4. **无关修改不重建**：名称修改，以及未启用订阅的编辑、删除不再改变有效规则指纹。即使原始下载缓存丢失，也可根据事务前后有效配置和当前产物哈希确认无过滤变更；不会下载、重建 DNS 或重载代理。格式修改等经过预检的操作和主动刷新不能使用这条捷径。
5. **复用已知下载大小**：预检将实际字节数交给后端，正常配置下避免为同一新增列表再次发送 HEAD 请求查询大小；大小是统计元数据，不影响其他工具未提交编辑的保护。

## 各操作实际执行的工作

| 操作 | 下载和校验 | 重建及重载 |
| --- | --- | --- |
| 页面上选择多项规则 | 暂存草稿，不下载 | 不重载 |
| 仅改名称或未启用规则后应用 | 核对配置和当前产物 | 有效配置未变时跳过 |
| 重新加载，配置和内容未变 | 核对已有证明与当前状态 | 跳过重复重建、重载 |
| 更新订阅，响应正文相同 | 每个启用源请求一次；复用有效解析结果 | 跳过重建，核对代理现状 |
| 域名/基础 Adblock 仅头部或顺序变化 | 校验新正文，并核对相同规则证明 | 跳过重建，核对代理现状 |
| 新增、启用或修改有效来源 | 优先复用下载快照，缺失时下载，校验变化来源 | 需要时一次重建并同步 |

前后端操作仍在原有锁和事务中执行。旧页面、外部并发修改、损坏输出、未完成恢复和代理重载未确认状态不能用性能捷径绕过。NaiLink、PassWall、OpenClash、Nikki 的现有适配保留；真实过滤内容改变时仍有必要的生成和重载成本。

下载到缓存但整批未成功应用的内容，不能被名称修改或旧产物恢复顺带标成「已应用」。这些操作保留生成当前产物时的输入证明；下一次真正刷新仍能识别规则变化并重建。旧版产物证明采用不同版本，升级后不直接采信旧输入与产物的绑定；首次需要重新建立证明，随后才能使用对应的跳过优化。

## 真实来源对比的边界

这批 21 份 HTTPS 正文均通过生产解析器检查；其中 20 份与固定版本原生格式化后的完整域名集合完全一致。SomeoneWhoCares 的 `255.255.255.255 broadcasthost` 系统头部会被原生 sed 误拼成一条额外的 `255.255.255.255broadcasthost`。独立计数排除了系统头部，报告单独列出这个上游伪域名差异，没有将其当成广告域名，也没有把任意差异过滤掉再声称完全一致。

两个来源最初通过 Python 默认客户端返回 403，随后以 curl 获取到 HTTP 200 的列表；审计使用成功响应的正文及 SHA-256，未将客户端访问差异当成规则格式错误。上游内容和网络响应会变化，这批数据仅代表本轮快照。

证据见 [evidence/v0.10.4](evidence/v0.10.4/)。真实规则下载正文未随仓库再分发。性能实验使用真实 UCI/ucode/shell 和 206,375 条合成规则，但 DNS 服务、下载和代理重载为隔离夹具；不把实验时间当成用户 ARM 路由器耗时，也不将配置成功等同于 LAN 拦截验收。
