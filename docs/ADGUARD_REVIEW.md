# 参考 AdGuard 的优化方向

AdGuard 的客户端、浏览器扩展和 AdGuard Home 工作层级不同。AdZero 当前在路由器的 DNS 与代理规则层过滤，优先参考 AdGuard Home 的交互和诊断方式。

| 优先级 | 方向 | AdZero 当前状态与下一步 |
| --- | --- | --- |
| 高 | 即时反馈、可靠状态 | 已支持统计自动刷新；本轮让当前接入信息一起自动同步，并增加命中规则但返回正常 IP 的提示；可见页面每秒读取小快照，隐藏时暂停。 |
| 高 | 配置与实际加载分别检查 | v0.14.0 修正 OpenWrt 服务调度，核对 PassWall/SSR Plus+ 运行 DNS 的配置包含链和规则样本。未加载会提示并有限重试，避免配置已写入却误报同步。 |
| 高 | 避免分流规则绕过过滤 | PassWall 不论是否启用 AdZero 自动分流，都为原生转发列表中命中屏蔽父域名的子域名补齐屏蔽项；SSR Plus+ 同样处理其原生列表。 |
| 高 | 查询原因与快速放行 | 已有域名命中查询、放行、撤销和临时暂停；后续可增加明确的规则来源解释。 |
| 中 | 最近拦截记录 | v0.13.0 已加入手动开启的 5 分钟、最多 30 域名内存列表；检查当前匹配范围后再确认放行。 |
| 中 | 客户端维度 | 后续可按设备汇总可观察请求；需先验证多网段、IPv6、缓存与加密 DNS 的覆盖，不能把接口统计当作全部请求。 |
| 中 | CNAME 追踪规避 | AdGuard Home 会检查响应里的 CNAME。AdZero 当前依赖已有后端和代理的规则能力，不能把抓包观察器当作可修改响应的 DNS 服务。该能力需要另外设计与端到端验证。 |

规则更多不等于效果更好：重叠列表会增加处理量；过强列表可能误杀。继续保留批量应用、本地缓存复用、下载更新和手动校验分开，优先把常见广告、追踪与误杀处理做稳定。

后续优先级：显示命中规则来源，帮助定位误杀；为更多原生 DNS 生成器补充独立验收；最后再评估 CNAME 响应过滤和按设备策略。后两者需要扩展实际 DNS 处理能力及隐私设置，本轮没有将其伪装为已实现的观察统计。

同域视频广告、网页元素隐藏与广告留下的空白不能靠 DNS 全面解决，本版不作此承诺。新代理兼容同样先核对其原生 DNS 和规则扩展接口，再测试接入、切换与恢复；管理界面可访问不能代替代理内核运行的证据。
