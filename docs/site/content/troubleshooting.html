网站或 App 打不开

  1. 在概览临时暂停，对比同一个网站或功能。
  2. 若暂停后恢复，打开「访问控制」记录最近拦截，检查相关域名与影响范围。
  3. 先临时放行确认，确有必要再加入永久放行。
  4. 暂停后仍异常，检查代理独立联网、DNS 答案和设备是否绕过路由器。

没有广告并不表示能去掉所有网页空白；同域视频广告也可能无法用 DNS 单独过滤。

数字不变或显示待验证

确认统计组件就绪，并从终端发出新查询。DNS 缓存、加密 DNS、没有新广告请求都可能使计数不变。“待验证”需要电脑执行效果检测命令；不要靠重复手动校验规则来解决。

DNS请求拦截占比不能判断漏拦。如果已知广告域名仍返回真实 IP，先在“访问控制”查询它是否命中当前已应用规则，再用故障设备完成效果检测。未命中应检查规则与放行范围；命中仍返回 IP 则检查接入、IPv6 或设备独立加密 DNS 路径。只看到加密流量或没有计数，不能直接认定绕过；严格模式也不覆盖任意浏览器 DoH。

计数增加但命中域名仍解析出公网地址，需同时检查规则查询结果、当前接入和实际 DNS 应答，不能只改前端数字。

红条、等待锁、关闭并恢复

先展开错误详情，区分上次任务失败与当前保护状态。后台迁移或重载可能暂时持有操作锁；“等待锁超时”不代表已经关闭。等待后点击「重新检测」核对，不手动删锁或恢复记录。

确实要求恢复时，执行页面「关闭并恢复」并等任务结束。失败保留日志继续定位，不强行覆盖配置。

切换后 Google / ChatGPT 解析异常

若开启并发后出现故障，先看错误是否为国内 TCP 或国外代理 DNS 路径未通过。NaiLink 没有本机 SOCKS 时使用两组单一＋备用、严格关闭；PassWall 国外并发还要求原生 TCP DNS 引擎。不能把 UDP 测速通过当作并发路径正常。推荐起始设置。

先确认唯一活动代理和当前接入，再从故障电脑查询同一域名。比较新查询、旧连接、IPv4/IPv6 与可信加密路径的答案；NOERROR 只表示收到了 DNS 应答。

网络路径恢复后，Windows 可按需清除坏缓存，再重新打开受影响应用：

ipconfig /flushdns

这不能替代路由器修复。如果每次都需清缓存，或 TCP DNS 超时、nftset 持续报错，保留原文分别排查。不要全局清连接跟踪、盲目改全部上游或关闭路径安全检查。

安装时提示「不支持此固件 / 目标架构」

不是所有 OpenWrt、ImmortalWrt、iStoreOS 都能用同一个安装包。以 root SSH 运行 cat /etc/openwrt_release，核对固件 ID、完整版本、target 和包架构，再与支持固件表对比。iStoreOS 25.12 Beta 要核对修订号 2026102312，iStoreOS 24.10.8 OPKG Beta 要核对 2026073111，R6XS 还会检查板型。

请使用统一自动检测安装命令：它会在已发布的四种渠道中自动选一个，而不是让你手动下载对应版本。已下载后还可运行 sh /tmp/adzero-install-auto.sh --detect 进行不联网的只读识别。若你的固件不在支持表中，不要修改 DISTRIB_ID 或强装其他 target；可以提交适配需求。

iStoreOS 24.10.8 提示 OPKG/IPK 或版本不匹配

24.10.8（revision 2026073111）使用 OPKG/IPK，不能直接安装 iStoreOS 25.12 的 APK。本项目只对 x86_64、ARMSR 和原厂 R6XS 三种精确 target 开放 24.10 Beta.1 公测。运行统一安装命令会自动识别。其他 24.10.x、不同 revision 或错误架构必须停止，不要强制安装或更改系统标识。

请先从菜单选择只读预检，再尝试「安装但不启用过滤」。本通道包含原厂真实 OPKG 格式 IPK 和七份匹配的依赖包；若模拟提示安装其他包、升级系统软件或恢复失败，请保留错误详情并提交反馈。

iStoreOS 25.12.6 提示「目标需要 APK，当前包管理器或数据库不匹配」

这条报错可能来自旧版统一安装器使用固定数据库路径或将历史 OPKG 状态文件当成有效包管理器。请重新执行最新的一条命令下载新版安装助手；它会自动选择 iStoreOS Beta.3，通过真正的 apk info -e 查询本机软件包，而不是凭遗留路径判断。

如新版本仍报错，可只读执行 cat /etc/openwrt_release、apk --print-arch、apk info -e base-files luci-base rpcd tcpdump 并反馈脱敏后的结果。若这些必要组件确实不存在，程序仍会安全拒绝安装。不要删除 OPKG/APK 数据库、强制安装或绕过 SHA-256 校验。

公测版依赖下载失败 / 软件包被拒绝

ARM64 Beta.2 缺少依赖时，只接受当前固件对应的官方 HTTPS 软件源，或已经列入白名单的中科大对应厂商 HTTPS 镜像。使用其他镜像、旧补丁版本源、混合两种版本，或原厂依赖无法获取，安装器会停止。先检查路由器原有仓库是否匹配固件，不要关闭 SHA 验证、禁用证书校验或手动添加其他固件的 feeds。

iStoreOS Beta 则自带每种目标的原厂依赖，安装前检查全部 APK。如果提示压缩包 SHA-256 不匹配、原厂 tcpdump 将被替换、板型不符或已有 AdZero，应该停止，保留错误信息；不要用 --force 或人工改包名绕过。

如果已安装 iStoreOS Beta.1 / Beta.2，统一安装入口会选择最新 Beta.3 菜单；OpenWrt / ImmortalWrt ARM64 继续选择 Beta.2。先在对应菜单执行「安全卸载」（需确认关闭和恢复 DNS/代理），再安装新版本；不要通过覆盖安装或删除安装标记升级。

升级失败

“没有唯一匹配的 SDK 包”需核对完整固件版本、设备 target 和包架构；“软件源更新失败”需检查对应固件的官方软件源。独立 ARM64 / iStoreOS Beta 不会通过 LuCI 常规更新按钮自动升级，需要使用各自的独立菜单。已有可用版本时先保留配置和状态，不要为了重试而直接删掉旧包。
