网站或 App 打不开

  1. 在概览临时暂停，对比同一个网站或功能。
  2. 若暂停后恢复，打开「访问控制」记录最近拦截，检查相关域名与影响范围。
  3. 先临时放行确认，确有必要再加入永久放行。
  4. 暂停后仍异常，检查代理独立联网、DNS 答案和设备是否绕过路由器。

没有广告并不表示能去掉所有网页空白；同域视频广告也可能无法用 DNS 单独过滤。

数字不变或显示待验证

确认统计组件就绪，并从终端发出新查询。DNS 缓存、加密 DNS、没有新广告请求都可能使计数不变。“待验证”需要电脑执行效果检测命令；不要靠重复手动校验规则来解决。

计数增加但命中域名仍解析出公网地址，需同时检查规则查询结果、当前接入和实际 DNS 应答，不能只改前端数字。

红条、等待锁、关闭并恢复

先展开错误详情，区分上次任务失败与当前保护状态。后台迁移或重载可能暂时持有操作锁；“等待锁超时”不代表已经关闭。等待后点击「重新检测」核对，不手动删锁或恢复记录。

确实要求恢复时，执行页面「关闭并恢复」并等任务结束。失败保留日志继续定位，不强行覆盖配置。

切换后 Google / ChatGPT 解析异常

先确认唯一活动代理和当前接入，再从故障电脑查询同一域名。比较新查询、旧连接、IPv4/IPv6 与可信加密路径的答案；NOERROR 只表示收到了 DNS 应答。

网络路径恢复后，Windows 可按需清除坏缓存，再重新打开受影响应用：

ipconfig /flushdns

这不能替代路由器修复。如果每次都需清缓存，或 TCP DNS 超时、nftset 持续报错，保留原文分别排查。不要全局清连接跟踪、盲目改全部上游或关闭路径安全检查。

升级失败

“没有唯一匹配的 SDK 包”需核对固件、目标和架构；“软件源更新失败”需检查报错的软件源。保留安装版本与保护状态，修复安装条件后重新升级，不要先卸载当前可用版本。
