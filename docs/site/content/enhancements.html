默认关闭，按需开启。这里的增强功能不是普通过滤的前置条件。先保持当前网络正常，再启用需要的项目。

页面将「增强过滤」与「上游与备用」分开显示，适用范围和测试说明可展开查看。国内、国外组直接显示已保存的 DNS 地址；尚未测试也能看清当前地址和备用项。

添加或修改 DNS

  1. 在「上游与备用」点「编辑 DNS」。国内、国外各每行一个 IP，最多八个；第一条优先，其余为同组备用。
  2. 点「保存到待应用」，再点页面上方「应用并重新加载」。暂存期间显示「待应用」，不会把旧测试耗时当作新配置结果。
  3. 修改开关、测试端口或设备规则后，另点底部「保存增强设置」。有未保存或待应用更改时，测试按钮会暂停使用并显示原因。

地址编辑使用共享的 DNS 与分流设置。自动分流关闭时只保存地址，不会自动接管代理 DNS；需要让这些地址用于分流时，在「运行概览 → DNS 与分流」启用自动分流并统一应用。当前只接受 IP 地址和标准 53 端口，不接受 DoH/DoT 网址或自定义端口。

上游连通性测试

进入「DNS 增强」，测试已保存的地址。国内组用 UDP 直连；国外组通过明确配置的本机 SOCKS5 TCP 端点测试，需要填写真实可用的本机无认证 SOCKS5 端口。

程序不会猜端口或选择代理节点；没填端点时跳过国外测试，不用直连结果冒充代理测速。结果只代表指定路径的连通性和耗时，不能验证 DNS 是否被污染，也不等于网站登录或 API 可用。

SOCKS5 端口应从当前代理的本地监听设置中确认，不能填 DNS 的 53 端口，也不要直接照抄界面的示例数值。保存后点「测试 DNS」，结果会在组内按地址更新；更换 DNS 地址或国外测试端口后，旧结果标为「需重测」。

同组备用切换

默认关闭。启用需要 AdZero 自动分流已经实际应用。每分钟一轮检测，连续三轮失败、有健康备用且满足至少五分钟冷却，才尝试切换；只在国内组或国外组各自内部选择，不会因一次慢查询重载。

遇到并发修改或适配失败会保留原因，不覆盖新设置。请先配置可用的地址与国外 SOCKS5 路径，再考虑自动备用。

增强 DNS 入口适用范围

当前仅支持可确认的系统默认 dnsmasq.servers 或 PassWall 默认 IPv4 LAN DNS 路径，不支持自定义 ACL、IPv6 接管、多代理和不稳定的切换状态。NaiLink eBPF、OpenClash/Nikki 的 Mihomo/Fake-IP 路径不会启用此入口；这些代理的基础广告过滤仍可使用。

增强入口沿用原生上游与缓存，不新增共享缓存；仅使用 AdZero 自己的接管表。退出或服务不可用时尝试移除接管，回到原生路径。未知网络结构不会猜测接管。

同一客户端的 TCP DNS 会复用自己的原生连接，减少重复建连；上游关闭时有限重连，不在设备间共享回答。域名查询、手动校验保持增强入口运行，修改网络配置时仍暂时退出接管。

若显示“增强入口退出待确认”，表示接管或旧 DNS 会话清理尚未完成。恢复记录会保留，请查看日志定位原因，不要手动删除记录或全局清空连接。

CNAME 别名过滤

在支持的增强入口中，检查实际 DNS 应答里从查询名称可达的 CNAME 别名链；别名命中当前规则时阻断。它可补充部分追踪域名覆盖，不能覆盖绕过入口或同域广告。

设备附加规则

按固定的局域网私有 IPv4 设置附加放行和拦截。最多三十二台设备，每台各三十二条；建议先在 DHCP 设静态租约，避免地址变化后规则对应错设备。

设备放行只豁免该设备的附加/CNAME 过滤，不能覆盖全局名单、订阅或其他插件的原生拦截，也不是给设备关闭全部广告过滤。附加命中单独统计，避免与概览被动统计重复累加。
