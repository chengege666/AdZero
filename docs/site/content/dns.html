默认地址与路径

在「运行概览 → DNS 与分流」统一设置两组地址、查询策略、严格模式和本机 SOCKS5 端口。「DNS 增强」测试同一份保存配置，通过“管理 DNS 与分流”回到这里。

支持有效 IPv4/IPv6 数字地址与标准 53 端口，不接受 DoH/DoT 网址、域名或任意端口。两组实际参与查询的地址不可重叠。普通 TCP DNS 本身不加密，代理传输与节点出口的加密范围取决于所用协议。

修改与应用

  1. 每行一个 IP，选择“单一 + 备用”或“组内并发”。
  2. 按需设置本机无认证 SOCKS5 端口；国外测试使用，NaiLink 严格模式、PassWall 国外并发及严格 TCP 模式必填。
  3. 保存到待应用，核对规则和分流草稿，再点一次「应用并重新加载」。

单一模式最多八个地址，仅第一条参与查询，其他为同组备用。并发模式最多三个地址同时查询，采用首个有效应答；格式错误、查询不匹配或失败应答不会抢先胜出。国内、国外不跨组竞争。并发增加请求量，不能把污染应答自动变成可信答案。

升级保留原模式，不自动开启并发或严格模式。恢复默认也先进入草稿，不立即改网络。并发模式不再做备用轮换。

自动分流要不要开

普通广告过滤无需开启自动分流。需要由 AdZero 设置国内直连、国外经当前受支持代理的 DNS 与分流时，再开启。关闭时保留个人地址库；设置通常在下一次开启自动分流时使用。

PassWall 保留原有 dnsmasq 或 ChinaDNS-NG 引擎和原生节点、分组策略。AdZero 不保证任意代理引擎或自定义 ACL 都支持自动分流；无法确认时会提示，不强制转换引擎。

严格 DNS 防旁路

默认关闭，需要自动分流与唯一活动的受支持代理、单个默认 IPv4 LAN、端口 53 的单个 dnsmasq，以及 nft / conntrack。代理接入未确认时阻断 DNS；通过 UDP/TCP 应答检查后开放。切换期间通常在下一轮五秒检查中发起恢复，实际耗时取决于代理；不会因代理失败回落到国内组或直连。

  • 接管默认 IPv4 LAN 的 UDP/TCP 53，阻断该 LAN 的 IPv6 DNS 与 TCP/UDP 853；其他 IPv6 数据继续保留。
  • 国内生效 DNS 组保留为代理节点引导解析例外。这不是零外发承诺；其他进程显式查询这些例外地址也不在“国外组不直连”保证内。
  • 浏览器／应用内置 DoH 经 HTTPS 443，需在设备侧关闭或统一管理。此版不解密 HTTPS，不阻断全部 443，也不声称覆盖任意 DoH、其他 VLAN、VPN 或绕过本路由器的流量。
  • PassWall 严格模式要求默认 DNS 接管与本机代理开启，没有启用的自定义 ACL。SSR Plus+ 暂不支持。
  • 严格模式期间不接入可选 CNAME／设备增强入口，也不提供临时暂停。关闭并恢复仍可使用；恢复冲突保留记录，不覆盖手动设置。

关闭严格模式后按记录交还 DNS 和防火墙；OpenClash 原生 DNS 快照交接单独核对，避免保留旧代理端口。不要手删恢复记录、防火墙或操作锁。

怎样判断解析速度

先看概览当前路径的正常 DNS 应答耗时，再用上游测试比较同组地址。第一次查询和命中缓存的耗时不同，不要只看一次测试就换地址。

DNS 返回了地址或 NOERROR，不等于地址可靠、代理出口正确或网页可访问。怀疑污染时需对照可信路径；切换后坏缓存与旧连接问题见解析异常。
