现在只需要一条安装命令。统一安装助手会自动识别 OpenWrt、ImmortalWrt、iStoreOS 的固件版本、设备 target 和 CPU 包架构，再打开对应的中文菜单。不支持的设备直接拒绝，不强行安装。

复制这一条命令，自动识别安装

以 root 身份登录路由器 SSH，复制下面整行执行：

curl -fL --proto '=https' --proto-redir '=https' https://raw.githubusercontent.com/slobys/AdZero/main/scripts/install-auto.sh -o /tmp/adzero-install-auto.sh && sh /tmp/adzero-install-auto.sh --menu

不需要自己选择固件类型、版本或 CPU。助手先只读检查系统，再下载唯一匹配的安装器并校验 SHA-256，然后才进入原有菜单；运行这条命令本身不会直接安装、升级或开启过滤。

需要只看识别结果，可运行 sh /tmp/adzero-install-auto.sh --detect（不会联网）；仅预检可运行 sh /tmp/adzero-install-auto.sh --check（可能下载所选安装器并检查官方软件源）。

自动识别会选择哪个渠道？

支持的固件与版本表列出了全部精确组合。简单来说：

检测到的固件自动进入的安装菜单
OpenWrt 24.10.8 / 25.12.5、ImmortalWrt 24.10.6 / 25.12.2 的指定常规目标常规安装菜单
OpenWrt 25.12.6 / ImmortalWrt 25.12.2 的 Rockchip ARM64 或 MediaTek FilogicARM64 公测菜单
iStoreOS 25.12.6（修订号 2026102312）的 x86_64、ARMSR 或 Rockchip R6XSiStoreOS 公测菜单
iStoreOS 24.10.8（修订号 2026073111）的 x86_64、ARMSR 或 Rockchip R6XSiStoreOS 24.10 IPK 公测菜单

这是四种自动选择的发行渠道，用户不需要从中手动挑命令。助手会核对固件、完整版本、target、架构；匹配失败就提示原因并停止。常规版和公测版的独立发行包仍互不混用。

常规安装：OpenWrt / ImmortalWrt

适用于已有 SDK 构建包的五组精确固件目标。统一安装助手会自动进入常规安装菜单，无需填写固件或架构。

进入中文菜单，选择兼容检查、安装、安装但暂不开启、升级或安全卸载。安装包按当前固件自动匹配，不需要手动输入 CPU 架构。常规发布版本为 $release（当前同样标记为 Pre-release，SDK 编译不等于所有真机认证）。

ARM64 公测：OpenWrt / ImmortalWrt 新目标

仅适用于 OpenWrt 25.12.6 或 ImmortalWrt 25.12.2 的 rockchip/armv8、mediatek/filogic 指定架构。统一安装助手会自动进入独立 ARM64 公测菜单，并不会把任意 ARM64 都当成支持。

安装器会自动选择四个原厂 SDK APK 中的匹配包，先模拟依赖安装。缺少依赖时只接受匹配固件的官方 HTTPS 软件源或中科大对应厂商 HTTPS 镜像，并严格核对固件版本与架构；源不匹配、依赖不齐或准备替换系统原包时立即停止。首次安装默认不启用 DNS 过滤。

iStoreOS 公测：x86_64 / ARMSR / R6XS

仅适用于 iStoreOS 25.12.6、修订号 2026102312 的 x86_64、ARM64 ARMSR 和原厂兼容的 Rockchip R6XS。统一安装助手会自动进入 iStoreOS 公测菜单，R6XS 还会额外核对板型。

每种设备的安装包都含 AdZero 本体及六个对应原厂依赖，安装前验证 SHA-256 和离线依赖计划。Beta.3 已修复旧版对 APK 数据库路径或历史 OPKG 文件的误判，改为通过当前 APK 已安装包查询验证。首次安装默认关闭 DNS 过滤，不自动更改原有 DNS/代理路径。

iStoreOS 24.10.8 公测：原生 OPKG/IPK

只适用于 iStoreOS 24.10.8，修订号 2026073111 的 x86/64、armsr/armv8、R6XS rockchip/armv8 三个严格目标。统一入口会自动选择独立的 iStoreOS 24.10 Beta.1，不是新版 25.12 的 APK 安装器。其他 24.10.x 和不匹配的 Rockchip 板型仍被拒绝。

每个目标的安装包包含一份历史原厂 Buildroot 编译的 AdZero OPKG/IPK 和七个原厂 IPK 依赖，执行哈希验证和真实 OPKG 离线模拟，遇到已有软件包升级、删除或文件冲突时停止。首次默认不启用 DNS 广告过滤，请先在可救援的测试设备上确认正常网络和原有代理。此渠道尚待真实设备安装和 DNS/代理共存验收。

安装成功后做什么？

  1. 先确认仍能进入 LuCI / SSH，正常网站能打开。
  2. 进入 服务 → AdZero，到「过滤规则」选择列表并应用。
  3. 回到「运行概览」开启保护，再从电脑检测广告域名与正常域名。

公测版建议先安装不启用，等正常上网和原代理确认无误，再手动开启。首次试装优先使用有备用管理方式的设备，并提前备份配置。

已安装 AdZero，怎么升级？

重新执行顶部同一条统一命令，会根据本机固件重新打开正确的安装菜单。常规渠道仍可以点击 LuCI Logo 旁的版本号检查匹配的常规更新；独立 Beta 不会被常规在线更新自动选中。

三个 Beta 仍是独立测试渠道，不提供跨渠道强制覆盖升级。已安装其他版本的设备必须先安全关闭、恢复原有网络设置，再从原渠道卸载。公测版可以通过统一入口进入对应菜单选择「安全卸载」；查看恢复说明。

路由器不能连接 GitHub？

统一入口需要联网下载匹配的安装菜单。如果路由器无法访问 GitHub，可在可信电脑上从对应的公开发行页下载专用安装器与安装包，复制到路由器后使用该原安装器的 --local-dir 参数。仍需检查固件和 SHA；ARM64 公测的缺失依赖可能需要官方仓库。

安装失败，怎么办？

先保留终端报错，不要更改 DISTRIB_ID、手动替换不匹配的 APK，也不要直接删除 DNS/代理配置。常见原因包括固件版本不一致、官方依赖源不可用、已有 AdZero 安装、备份或恢复任务仍在进行。按安装兼容问题和升级失败排查处理。
