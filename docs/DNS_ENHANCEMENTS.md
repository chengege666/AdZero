# DNS 增强

v0.19.1 起，此页只保留增强过滤入口、CNAME 别名过滤与设备附加规则。DNS 地址、组内策略、严格模式、上游测试和自动备用，统一在「运行概览 → DNS 与分流 → DNS 设置」。配置与分插件推荐见 [DNS 设置](DNS_SETTINGS.md)。

自动备用仅对单一模式生效，保留旧版选择；新入口的明确开关优先。CNAME／设备规则仍使用增强页底部「保存增强设置」。严格模式期间不接入这个可选入口，基础广告过滤仍可使用。

增强入口沿用原生缓存和上游，不改变代理节点。仅支持确认的默认 IPv4 系统 DNS 或 PassWall 路径；NaiLink、OpenClash/Nikki、未知 ACL 和切换期间保留原生路径。设备放行只豁免本设备的附加过滤，不能覆盖全局规则。完整范围见 [在线增强说明](https://slobys.github.io/AdZero/enhancements.html)。

v0.19.2 补充 HTTPS（65）／SVCB（64）应答中的 AliasMode（优先级 0）别名，并让设备附加拦截检查可达的别名目标。只沿当前问题名称的应答链检查；普通 ServiceMode、无关记录、附加区及不匹配的问题类型不用于别名拦截。显式放行、截断与错误应答的原有边界保留。记录只按查询类型生效，不能把 HTTPS 别名应用到 A/AAAA；见 [RFC 9460](https://www.rfc-editor.org/rfc/rfc9460.html#section-2.4.2)。

增强页的“别名拦截”计数包含上述别名检查；概览仍只统计可观察且命中当前主规则的 A/AAAA 查询，两者不直接相加。增强入口仍需显式开启且路径受支持；本次不自动更换代理 DNS、开启严格模式或阻断浏览器 HTTPS/DoH。

## 实现顺序

1. 在既有访问控制事务中加入临时例外，使用启动标识和单调时钟，到期批量恢复，失败保留日志并重试。
2. 使用当前输出摘要和已应用来源凭据解释命中；不把当前下载缓存直接当作生效来源。
3. 以小型 ucode socket 模块实现有界的 DNS 探测和增强入口，不新增大型 DNS 服务。国内 UDP；国外通过明确配置的本机 SOCKS5 TCP 端点探测。缺少端点时不把直连测速当代理测速。
4. 增强入口仅在可确认的系统 DNS 或 PassWall 默认 IPv4 LAN 路径接入，保留原生上游与分流。未知 ACL、多代理、代理切换中、NaiLink eBPF、Mihomo Fake-IP 不猜测接管。
5. CNAME 只检查当前应答中由问题名称可达的别名链；设备附加名单按明确 IP 匹配。设备放行仅豁免该设备的附加拦截，不覆盖全局和其他插件原有规则。

## 网络和数据约束

- 增强入口默认关闭；不修改代理节点、用户防火墙表或全局连接记录。接管仅使用 AdZero 自己的 nft 表。
- 接管前先监听并确认原生 DNS 上游；退出、暂停、切换、进程停止时移除自己的表。服务不可用时放回原生路径。
- 不添加另一层 DNS 缓存；原生缓存继续生效，避免设备策略或临时规则被共享缓存跨设备复用。
- 原始 UDP/TCP DNS 透传，保留 EDNS；过滤时清除 DNSSEC AD 位并返回零 TTL 的空答案。
- 有界连接、消息、别名深度和上游等待；客户端身份只用于本地策略，不保存完整查询日志。
- 备用只在同组内选择。自动切换需连续失败、可用备用和冷却，不因一次慢查询重载代理。
- 隔离测试和 SDK 构建不能代替用户路由器与原电脑验收。
