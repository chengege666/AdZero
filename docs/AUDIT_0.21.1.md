# v0.21.1 DNS 并发启动审计

## 根因与范围

安装版 v0.20.5 的 `prepare_pool()` 与 v0.21.0 中的同一函数一致。四次生产日志均先载入 246,924 个域名，再连续报告 30 次 `sleep: invalid number '0.1'`，随后因入口未就绪而撤销开启。这一证据指向等待兼容性缺陷，没有本次规则容量超限的证据。

在私有网络命名空间和校验过的 OpenWrt 根文件系统中，禁用 BusyBox 小数秒支持，原函数约 0.03 秒就误判失败；生产函数改为原生等待后，650 毫秒延迟的真实入口约 0.75 秒就绪。没有健康记录时仍等待约三秒后失败，不会通过放宽保护来伪装成功。`sleep()` 的毫秒单位见 [ucode 官方文档](https://ucode-lang.org/ucode/module-core.html#sleep)。

## 修改文件

| 文件 | 修改目的 |
| --- | --- |
| `dns-pool-state.uc`、`adapter.uc` | 共享健康校验与单调截止时间；使用原生毫秒等待，保留文件和配置保护；复用现有健康实例，忽略旧尝试的失败回执。 |
| `dns-pool.uc` | 记录健康进程身份；真实监听／运行错误使用固定原因回执，不发布假健康记录。 |
| `ctl`、`progress-lib.uc`、rpcd `adzero` | 保留启动原因，只有整个回滚成功才标记已恢复；恢复未确认时继续保留恢复资料。RPC 严格限制公开原因和恢复状态。 |
| `overview.js` | 展示启动原因与恢复结果；关闭保护时不再暗示过滤仍在工作。 |
| `test_dns_pool_start.py`、`test_ctl.py`、`test_view.cjs`、`check_rpc.py` | 延迟启动、截止时间、无效健康、真实控制器恢复、RPC 脱敏和页面语义回归。 |
| `check_dns_pool_runtime.py`、CI、打包清单 | 将异步服务管理与真实 DNS 进程组合验证，确认新模块确实随包安装。 |

## 验证

- 原生 ucode：650 毫秒、1 秒、接近截止期限就绪；始终未就绪；启动请求失败；旧失败回执；配置不符、记录陈旧、权限／链接／大小异常、进程无法确认。
- 真实 DNS 进程：国内并发、国外并发、两组并发、严格配置经本机 SOCKS，以及失败后的再次启动，共 120 次 UDP／TCP、A／AAAA 查询。5356、5357、5358 各自 UDP／TCP 占用的六种情况均拒绝接入并报告监听失败。
- 控制器确认回滚成功后才公开“原配置已恢复”；回滚失败保留未确认状态。原先的广告过滤、放行、DNS 出口、规则容量、切换与冲突保护继续执行完整回归。

详细计数、SDK 与交付检查见[同一源码验证摘要](evidence/v0.21.1/summary.json)。真实进程验证使用私有异步服务管理夹具，不替代生产 procd、代理接管、终端缓存或 HTTPS 验收。用户的诊断脚本仅用于阅读对照，没有执行其 SSH 命令，没有部署报告附带补丁。
