# v0.20.4 事务与恢复审计

审计对象是当前源码、实际 OpenWrt 用户态运行时和隔离代理环境。没有连接用户路由器，没有修改网络配置。原有未提交的独立 DNS 架构草案及诊断资料保持原样。

## 已复现并修复

| 问题 | 触发条件与影响 | 修复及回归证据 |
| --- | --- | --- |
| 部分规则重建路径缺少提前预检 | 在线改名称、停用或移除订阅时，现有输出证明已失效；剩余来源可能重新下载，不能再假设它们与原来相同。旧实现会先提交，再进入后端重建，失败时还需恢复重载。 | 在候选仍处于内存时判断能否直接复用；需要重建则检查剩余来源，失败不提交、不停后端、不建立待恢复事务。三项用例同时检查配置原文、任务原因、恢复记录和后端调用次数。 |
| 旧恢复记录被误判为配置冲突 | 旧版 schema 1 规则事务及 schema 2 缓存保存了校验计数和时间，新版实时模型已忽略这些字段；直接比较会拒绝原本一致的恢复记录或错失缓存恢复。 | 对实时模型及保存模型使用相同的统计字段白名单，保留源身份、所有实际选项及顺序。测试旧记录确认、原文回滚、缓存启动，以及不把更新但未应用的快照认作已应用输入。真实选项差异仍拒绝恢复。 |
| 页面可能误清除真实冲突 | 后台重载结束后，规则行碰巧与旧草稿一致，但其他受保护设置存在已确认的冲突。原来的自动确认只比较可见行、分流与 DNS。 | 已确认冲突、当前写入任务和仍在进行的后台操作禁止自动确认；保留原草稿和差异提示。延迟回执成功后正常确认的原有测试继续通过。 |

主要实现修改是 `sources.uc` 和 `overview.js`；回归用例位于 `test_source_cache.py`、`test_sources.py`、`test_view.cjs`。包版本、安装器和在线文档同步更新，没有增加运行依赖。

## 审计覆盖

| 链路 | 检查重点 | 验证方式 |
| --- | --- | --- |
| 规则选择与应用 | 空选择、容量合并、未知格式、真实配置冲突、下载期间外部修改 | 实际 ucode/libuci 事务测试；源码核对 |
| 更新与缓存 | 下载失败、内容损坏、相同内容、语义等价、原生定时更新、未应用快照 | 摘要与输入证明测试；快照重放和原生输出变化用例 |
| 误拦截管理 | 手动名单、临时放行、到期与重启恢复、外部修改保护 | 访问控制与策略事务回归 |
| DNS 与代理切换 | 稳定采样、互斥操作、并发组边界、严格模式退出恢复、旧 DNS 会话范围 | DNS、守护和代理测试；实际 Mihomo、PassWall 隔离检查 |
| 页面与任务状态 | 草稿/已应用区分、超时回执、后台迁移、重载与冲突提示 | 界面状态断言；已有桌面和移动布局基线 |
| 安装交付 | 配置保留、失败恢复、官方 SDK 包、权限、发行文本与摘要 | 原生运行时全量检查、三种 SDK、实际发行包交付测试 |

本次没有改 DNS 转发规则或代理选择。全量检查及构建的具体结果见[发行验证记录](evidence/v0.20.4/summary.json)。没有把隔离测试写成真实路由器或终端验收。

## 仍需明确的边界

- 容量预检是域名候选计数和格式检查，不是 adblock-fast 的完整隔离构建。服务重载阶段的失败仍使用现有恢复记录处理；无中断地替换整套后端输出需要单独设计和验证。
- 严格 DNS 模式针对默认 IPv4 LAN 明文 DNS 路径；浏览器 DoH、不同 LAN/ACL、各种固件及代理版本不能仅凭一次构建宣布全部兼容。查看[DNS 设置范围](DNS_SETTINGS.md)。
- 持续跟踪真实终端在切换后的 DNS 答案、TCP/UDP 和 IPv6 路径，才能判定有无漏拦或绕过；本轮没有新增实机证据，也没有更换用户当前上游。
- 缩小代理重载影响和独立 DNS 服务架构可继续评估，但需覆盖 procd/jail、开机恢复和软件包迁移，不适合在一次维护修复中直接替换。
